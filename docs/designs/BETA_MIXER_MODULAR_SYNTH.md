## Vision (12 months)

Stim som live-instrument, inte ett verktyg där man redigerar JSON-filer. β-wedgen
är **modular synthesizer** med stim-output istället för audio: LFOs som genererar
rörelse, mixer som routar signaler till elcon-par, patch-cables som binder ihop.

α2 gav "se vad boxen genererar". β ger "spela boxen som ett instrument".

### 10x Check

Inte "pattern editor" (ursprunglig TODOS.md-framing). Det är **modular synth-paradigmet**
applicerat på stim. Reason/Eurorack mental-modell: oscillatorer modulerar parametrar
via patch-cables, knobbar är base-värden som signalen swingar runt.

## Premise locks

- **Reason-style modulation:** Knob-position rör sig inte visuellt under LFO-mod.
  Knob = user-set base. LFO oscillerar runt det. UI kan visa halo/ring för
  swing-range (γ).
- **Per-channel pace = per-channel emit-rate.** Varje channel är en "egen klocka"
  som tickar enligt sin (LFO-modulerade) pace. Channels interleave på wire.
- **nrOfPulses=1 i mixer-mode.** All bursting via host-streaming, inte
  firmware-side pulse-grupper. Matchar user-clarification.
- **Pure-TS DSP.** Inga Web Audio off-label. Egna sine/saw/square-formler,
  bun-test:bara.
- **Hardware bounds clampas alltid:** pulse_width 2..200µs, pace 5..62.5ms,
  amp 0..255. Single chokepoint i synth-engine.
- **Befintlig safety-stack inerverbar:** ramp-controller + max-ceiling + STOP
  watchdog applicerar precis som i α (inga ändringar i safety-modulen).

## Datamodell — Mixer + Synth state

```typescript
// src/synth/types.ts

export interface KnobState {
  /** User-set base value, hardware-units (µs/¼ms/0..255). */
  base: number;
  /** Optional cable som modulerar denna knob; null = static. */
  modCableId: string | null;
}

export type WaveShape = 'sine' | 'saw' | 'square' | 'triangle';

export interface LFO {
  id: string;
  rate: number;        // Hz, 0.01..50
  amount: number;      // 0..1, master output gain
  shape: WaveShape;
  phase: number;       // internal radians, advances per tick
}

export interface MixerChannel {
  id: string;
  elcon: Elcon;        // [pos, neg] från befintliga types.ts
  knobs: {
    pulseWidth: KnobState;   // base 2..200µs
    pace: KnobState;          // base 5000..62500µs
    amplitude: KnobState;     // base 0..255
  };
  enabled: boolean;
  /** Internal: when next pulse emits (sim-time µs). */
  nextEmitMicros: number;
}

export interface Cable {
  id: string;
  sourceLfoId: string;
  destChannelId: string;
  destKnobName: 'pulseWidth' | 'pace' | 'amplitude';
  /** Per-cable depth 0..1. Reason-style "modulation amount" knob på cable. */
  depth: number;
}

export interface MixerState {
  channels: MixerChannel[];
  lfos: LFO[];
  cables: Cable[];
}
```

## Synth-engine — Reason-style evaluation

```typescript
// src/synth/synth-engine.ts

/** Evaluera knob: base + signal × depth × hardware-range, sedan clamp. */
function evaluateKnob(
  knob: KnobState,
  knobBounds: { min: number; max: number },
  t: number,
  state: MixerState,
): number {
  if (!knob.modCableId) return knob.base;
  const cable = state.cables.find(c => c.id === knob.modCableId);
  if (!cable) return knob.base;
  const lfo = state.lfos.find(l => l.id === cable.sourceLfoId);
  if (!lfo) return knob.base;

  const signal = computeLfoSignal(lfo, t);          // -1..+1
  const range = (knobBounds.max - knobBounds.min);
  const swing = signal * cable.depth * lfo.amount * (range / 2);
  return clamp(knob.base + swing, knobBounds.min, knobBounds.max);
}

/** Tick:as från host-side waveform-loop (eller separat 5ms-tick). */
export function tick(simNowMicros: number, state: MixerState, sink: (d: PtDescriptor) => void): void {
  for (const ch of state.channels) {
    if (!ch.enabled) continue;
    if (ch.nextEmitMicros > simNowMicros) continue;

    const pw   = evaluateKnob(ch.knobs.pulseWidth, PW_BOUNDS,   simNowMicros, state);
    const pace = evaluateKnob(ch.knobs.pace,       PACE_BOUNDS, simNowMicros, state);
    const amp  = evaluateKnob(ch.knobs.amplitude,  AMP_BOUNDS,  simNowMicros, state);

    sink({
      meta: 0,
      sequenceNumber: nextSeqNr(),
      phase: 0,                    // base phase; biphasic-flip handled by interleaving
      pulseWidthMicros: Math.round(pw),
      startTimeMicros: simNowMicros,
      electrodeSet: ch.elcon,
      nrOfPulses: 1,               // streaming model
      paceQuarterMs: Math.round(pace / 250),
      amplitude: Math.round(amp),
      deltaPulseWidthQuarters: 0,
      deltaPaceMicros: 0,
    });

    ch.nextEmitMicros = simNowMicros + Math.round(pace);
  }
}
```

## Temporal Interrogation (Hours 1-6+)

**HOUR 1 (foundations) — what does implementer need to know?**
- LFO phase: radians (0..2π) eller normalized (0..1)? **Decision:** radians,
  matchar matematiska sine-formler. `phase += 2π × rate × dt`.
- Cable can-only-source-LFO eller can-source-anything? **Decision:** β.0 only LFO →
  knob. Knob → knob (envelope-following) is γ.
- Knob-bounds: where? `bounds.ts` exporterar konstanter. Single chokepoint för
  hardware-clamps.

**HOUR 2-3 (core logic) — what ambiguities will hit?**
- Tick rate: per-channel-pace (varje channel egen clock) eller global tick?
  **Decision:** global tick (5ms?), per-channel `nextEmitMicros` checkar inom.
  Enklare än per-channel timer-array.
- LFO depth interaction: `cable.depth × lfo.amount × range`? Eller bara
  `cable.depth × range`? **Decision:** båda multiplicerar — `cable.depth` är
  per-routing, `lfo.amount` är master på LFOn. Två gain-stages.
- Bipolar vs unipolar LFO: sine går -1..+1, men för pace (där 0 är ogiltig) kan
  modulation push under min. **Decision:** clamp till hw-bounds (inte mod-range)
  vid sista steget. User får visualfeedback att klippet sker via Oscilloscope.

**HOUR 4-5 (integration) — what will surprise?**
- Stop button behavior: pause synth-engine eller drain queue? **Decision:**
  pause + drain queue (befintlig STOP-flow). Ingen ny safety-path.
- LFO restart vid pattern-stop? **Decision:** phase fortsätter ackumuleras
  (free-running). Reason-default. Restart kan vara γ "one-shot mode".
- Channel-add med duplicate elcon? **Decision:** tillåt — användaren kan ha
  två "voices" på samma elcon med olika modulering. UI visar varning men inte
  block.

**HOUR 6+ (polish/tests) — wishes implementer kommer ha?**
- Knob double-click → reset till sensible default. Per knob: pw=144µs,
  pace=25ms, amp=128.
- LFO solo/mute för debug. Skip i β.0, lägg som TODO.
- Visualisera LFO-signal direkt i LFO-modulen (mini-scope inside LFO-panel)?
  Nice-to-have, inte β.0.

## Critical Risks (per Section 2-style review, compressed)

**Risk 1: Tick-rate mismatch.** Om global tick är 5ms och en channel har pace=7ms,
nästa-emit-check kan missa med upp till 5ms. **Mitigation:** Use per-channel
`nextEmitMicros` and let event-driven SimClock handle exact timing. ALTERNATIVT
ticka oftare (1ms) men mer CPU.

**Risk 2: LFO phase-drift mellan UI-display och synth-engine.** Om UI animerar
LFO-graf separat från engine, kan visa olika tid. **Mitigation:** Single source
of truth — `state.lfos[i].phase` är auktoritativt. UI läser bara, modifierar
inte.

**Risk 3: Cable-cycle (LFO → knob → ... loops).** Med bara LFO→knob (β.0) är
detta omöjligt. När vi senare lägger till knob→knob (γ), lägg cycle-detection
i routing.ts.

**Risk 4: Multi-channel kortslutning.** Channel A spelar A>B, Channel B spelar
A<B vid samma startTime → båda går till q0 (phase=0). Mock firmware queue gör
sin sak men hardware-routing kan momentärt ha alla 4 elektroder aktiva med
overlapping pos/neg. **Mitigation:** β.0 har bara 2 sub-queues (per phase),
hardware bör hantera per-burst-routing korrekt. E4 i TODOS för dedicated
analys när vi har real hardware.

**Risk 5: Drag-cable UX edge cases.** Drag cable utanför port → cancel? Drag
till samma port → swap? **Mitigation:** Decision i Hour 4 phase: drop-outside
= cancel, drop-on-occupied = replace existing, drop-on-source = no-op.
